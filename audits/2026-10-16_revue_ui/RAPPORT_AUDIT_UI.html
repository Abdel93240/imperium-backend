Les décisions prises en séance par le propriétaire sont déjà inscrites dans les docs et marquées COHERENT. Les données fictives des maquettes n'ont pas été prises pour des règles. Arbitrages demandés (14)

  1. UI-01 — Dashboard sans défilement : Règle « pas de défilement » absente des docs ; à tester sur appareil réel. Inscrire la règle dans 65 §3.3 (proposition).
  2. UI-02 — Contenus trop longs : Règle d'ellipse / nombre de lignes non définie. Proposition : ellipse sur 2 lignes + détail via le chevron.
  3. UI-03 — Journée entre sommeils : Les docs bornent la journée par les boutons, pas par la détection du sommeil principal ; siestes non décrites. Confirmer : fin = bouton « Terminer la journée » ; sieste = mission (à inscrire).
  4. UI-04 — Clôture de journée : Sort des missions encore actives non décrit (expirée ? reportée ?). Préciser le statut des missions actives à la clôture.
  5. UI-05 — Replanification : « Répétition immédiate » vs debounce_minutes = 5 (doc 43 §15, réglable). Arbitrer : le debounce s'applique-t-il aux replans demandés à la main ?
  6. UI-06 — Résultat et raisons : Pas de liste de raisons ni de sous-missions cochables côté backend ; les « missions annexes » du doc 53 sont V3 et un autre concept. Arbitrer : sous-missions V1 (champ à créer) ou retrait ; liste de raisons fixe.
  7. UI-07 — Pression et solde financiers : Jauge « faible à forte » à mapper sur les 5 libellés ; devises/crypto/transferts non vérifiés. Fixer la traduction FR des 5 libellés.
  8. UI-09 — Voix et terminal : Comportement au relâchement (envoi auto ou texte éditable) non défini. Arbitrer : transcription dans le champ, envoi manuel (proposition).
  9. UI-14 — Édition projet/mission : « Durée estimée » de mission absente du modèle ; « notes » projet = description ? Arbitrer l'ajout de estimated_minutes à la mission.
  10. UI-15 — Suppressions et dépendances : Effet en cascade (missions d'un projet supprimé, historique) non décrit. Préciser : missions passées conservées dans l'historique ?
  11. UI-16 — Récurrence routines : Modèle de données : routines = label + active ; ni fréquence, ni priorité, ni durée, ni notes ; ancrage de semaine non défini. Étendre le modèle routines (fréquence, priorité, durée, notes).
  12. UI-17 — Score régularité : Maquette « régularité sur 100 » : même score ×100 ? Fatigue/retards non pris en compte. Confirmer : régularité = discipline_score × 100.
  13. UI-18 — Portée période et bilan : — Inscrire le sélecteur (semaine, mois, 3 mois, année, tout).
  14. UI-24 — Priorités libres : Incompatible : la maquette permet une liste libre (ajouter, renommer, supprimer). Arbitrer : liste libre (migration) ou 4 domaines réordonnables.

Réponses documentées

NotificationsPush Android seul canal (Telegram éteint). Interrupteurs : check-in du matin, Weekly Review, rappels de mission, alertes rouges (désactivables). Docs 76 Q24, 43 §15, 65 §8.5. Maquette : brief B7.
Paramètres avancésUn menu, quatre entrées : vectorisation (ouvre la console de calibration sur la Tower), modèles par rôle (fournisseur / modèle / effort), seuils de score /200, clés API en écriture seule. Doc 73, doc 30 §3 et §5.6. Brief B8.
ConnexionClé maître uniquement : adresse du serveur + Tester (/api/health, /api/health/db), clé maître masquée jamais stockée, nom d'appareil prérempli ; un seul appareil de confiance, pas de liste. Doc 63 §13.5. Brief B9.
Gestion du widgetPas de widgets d'accueil. Bulles flottantes (overlay comme Bolt) : Imperium = mission en cours + Terminer / Échouer / replan complet ; Vault = ajout de transaction ; Path, Pulse, Vector = raccourcis. Doc 63 §10. Brief B6.
SuppressionsToujours une fenêtre de confirmation (doc 67, 71 §3.3). Nourrir l'IA : confirmation, puis le chatbot exécute la suppression de la source et des informations retenues et la confirme (doc 70 §4). Brief B2, B10.
